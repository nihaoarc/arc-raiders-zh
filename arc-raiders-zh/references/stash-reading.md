# 读取 ARC Raiders 仓库

## 通过 ARC Tracker 读取

- 每次用户要求同步、刷新或重新查询，都用已授权的 `arctracker` MCP 重新调用 `get_my_inventory`，以本次 API 响应为准。请求 `language: "zh-CN"`。查单个物品时传 `query`，按英文原名或物品 ID 核对实际匹配项。同一物品以 `items[].count` 为数量。多条近似匹配时先消歧。
- `appStash` 可确认有仓库记录，`readFromGame.at` 是该记录的游戏读取时间。用北京时间显示并说明数据时效。仓库占用、容量、种类数、总件数和界面估值分别取 `totals.stacks`、`capacity`、`distinctItems`、`units` 和 `stashValue`。账户余额另行核对。
- 完整清单先读汇总和第一页，再按 `nextOffset` 继续读取。用物品 ID 核对分页和匹配数。各页的 `readFromGame.at` 一致时才合并，必要时以最新一轮重读。记录缺失、分页未读完或匹配不确定时标明范围。
- 查仓库时使用玩家实际授权的库存工具。估算可出售数量还需要任务、工坊或项目需求等进度数据。仅有库存权限时 `safeToSell` 可能为空，根据用户提供的进度与可查证的需求计算。
- 库存响应缺少金币或奇袭者代币余额时，从已授权的账户页面或用户提供的截图核对余额与时间。
- `get_my_inventory` 读取 ARC Tracker 已保存的仓库记录。需要从游戏刷新时，按[连接与同步](arc-tracker-setup.md)尝试后台触发，完成后重新请求 API 核对 `readFromGame.at`。若游戏同步时间未推进，说明具体限制，并分别报告本次 API 查询时间和最近一次游戏同步时间。

## 单独的截图辨认任务

用户明确要求辨认游戏画面或截图时，按可见内容核对。Steam 版简中大厅底部的「物品栏」打开后，左侧是「储备箱」。仓库、装备栏和背包分别统计。

- 查看菜单、筛选、滚动和明确的物品详情入口。用右键菜单顶部的名称或提示卡确认同形图标，把每堆数量和耐久度分开。仓库估值和钱币余额分别记录。
- 盘点时在相邻画面保留重叠行，用行、列、图标和数量去重。只能核对可见范围时，把未读格和辨认不了的物品标为未知。全仓覆盖后可用占用格数核对。
- 对比玩家提供的历史快照时，核对每一份的读取时间、数据覆盖范围和数量口径。对局原因需要有对应战利品或装备记录支持。
